# 控制器调参与测试指南

## 文档状态

- 状态：Authoritative
- 适用对象：维护 PID/hold controller、teleop mixer、allocator 和控制侧回归测试的开发者

## 1. 当前控制器框架定位

当前控制仓已经具备可扩展控制器框架，但结论要说清楚：

- 当前 `Auto` 更接近 hold controller
- 已经支持 PID 系列框架化接入
- 还不能把现状描述成完整 trajectory tracking 或任务层自治

## 2. 控制器与混控关系

控制器输出的是控制目标或 wrench 语义，之后还要经过：

- `ControllerManager`
- teleop mixer / allocator
- `PwmClient`
- `orangepi_send`

因此调试时必须区分：

- 控制器本身算得对不对
- mixer/allocator 有没有把目标正确映射
- 执行侧保护有没有把输出压缩或截断

## 3. 关键配置入口

控制主线常看的配置包括：

- `pwm_control_program/config/control_params.yaml`
- `pwm_control_program/config/trajectory.yaml`
- `pwm_control_program/config/alloc.yaml`
- `pwm_control_program/config/teleop_mixer.yaml`
- `pwm_control_program/config/pwm_client.yaml`
- `pwm_control_program/config/config_reference.md`

改配置前先确认你影响的是哪一层，不要把控制器参数、混控参数和执行侧参数混改。

## 4. bench 联调建议顺序

最小联调建议如下：

1. 先跑 `gcs_server`
2. 再跑 `pwm_control_program --pwm-dummy --pwm-dummy-print`
3. 用 GCS 或最小输入链确认意图是否进入主循环
4. 观察 `TelemetryFrameV2` 和控制日志
5. 只有 dummy 链稳定后，再进入真实 STM32/PWM 联调

这样可以先把“控制语义问题”和“硬件执行问题”拆开。

## 5. 测试优先级

如果改动控制主线，优先回归：

- stale / failsafe / estop
- nav gating
- telemetry 组装
- `MotorTest`
- 关键 logger 与 timeline

如果改动控制器或 allocator，再补：

- 对应控制器单测
- `test_v1_closed_loop`
- `test_nav_reconnect_pipeline`
- 与配置相关的 smoke

## 6. 真实硬件联调注意事项

- 初次联调优先 dummy 后端
- 真实推进器联调前确认 estop、disarm、heartbeat 和回中保护
- 如果只需要验证协议或下发，不要顺手改控制器
- 如果问题是映射或 mixer，不要先怀疑协议层
