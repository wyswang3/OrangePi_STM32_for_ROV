# 控制系统总览

## 文档状态

- 状态：Authoritative
- 适用对象：维护控制主循环、gateway、telemetry 与 PWM 执行链的开发者

## 1. 仓库职责

`OrangePi_STM32_for_ROV` 当前负责：

- 接收 GCS 或本地意图并桥接到控制主链
- 消费导航视图并执行模式/安全裁决
- 运行控制器、混控与推力分配
- 生成权威 `TelemetryFrameV2`
- 通过 `orangepi_send` 把目标落到 STM32/PWM 执行链

它不负责：

- 导航滤波本体
- GCS UI
- 顶层 supervisor/operator 启动编排

## 2. 当前运行时主链

### 2.1 远程控制链

```text
GCS
  -> gateway/gcs_server
  -> /rovctrl_gcs_intent_v1
  -> pwm_control_program
  -> PwmClient
  -> orangepi_send
  -> STM32 / ESC / Thrusters
```

### 2.2 导航到控制链

```text
NavState
  -> gateway/nav_viewd
  -> /rovctrl_nav_view_v1
  -> pwm_control_program
```

### 2.3 遥测反馈链

```text
pwm_control_program
  -> /rovctrl_telemetry_v2
  -> gateway / telemetry_dump / GCS / ROS2 外围桥
```

## 3. 模块边界

### `pwm_control_program`

负责：

- 输入整合
- 模式与 guard
- 控制器管理
- 推力分配与 mixer
- telemetry 组装
- PWM client 驱动

### `gateway`

负责：

- UDP 会话与命令桥接
- `NavState -> NavView` 投影
- dump 工具和 bridge 辅助

### `orangepi_send`

负责：

- 协议打包
- UDP 发送
- PWM 安全层
- 心跳与基础链路状态

## 4. 当前 authority 边界

这个仓最重要的边界是：

- 最终 arm/disarm/estop/failsafe authority 在 `ControlGuard`
- gateway 负责桥接，不负责最终安全裁决
- `orangepi_send` 负责执行侧保护，不决定模式逻辑
- ROS2 只能处于外围层，不能接管最终 PWM authority

### 想看控制主线

4. `orangepi_send/src/libpwm_host.c`

## 6. 开发时最容易犯的错

- 把 gateway 当成最终控制 authority
- 把 GCS 键位映射和推进器混控混为一谈
- 把 `TelemetryFrameV2` 视为 UI 附带数据，而不是运行态权威视图
- 在没有明确边界的情况下，把模式逻辑塞进 `orangepi_send` 或 ROS2 bridge
