# 控制文档总览

## 文档状态

- 状态：Authoritative
- 适用仓库：`OrangePi_STM32_for_ROV`
- 目标：把控制、gateway、telemetry、PWM 执行链文档压缩为少量中文基线，避免协议、测试、阶段计划分散堆积

## 1. 这个仓的文档应该覆盖什么

控制侧文档只聚焦五件事：

1. 外部意图怎样进入控制主链。
2. 安全、模式、stale 和导航 gating 在哪里收口。
3. `TelemetryFrameV2` 与相关接口怎样定义运行态。
4. 控制器、混控、PWM 后端怎样落到执行链。
5. 后续演进时哪些边界不能破。

不作为本仓主入口的内容：

- 多仓启动说明
- operator 快速卡片
- 跨机器部署步骤

这些统一放在系统文档仓。

## 2. 当前保留的六份基线文档

1. `docs/文档总览.md`
   - 入口、阅读顺序、保留规则
2. `docs/控制系统总览.md`
   - 运行时主链、模块边界、代码入口
3. `docs/控制安全与运行语义.md`
   - `ControlGuard`、状态机、安全裁决与执行保护
4. `docs/通信协议与遥测说明.md`
   - GCS/gateway/SHM/`TelemetryFrameV2`/ROS2 外围边界
5. `docs/控制器调参与测试指南.md`
   - 控制器框架、混控、配置、回归与 bench 测试
6. `docs/演进记录与边界约束.md`
   - 阶段演进、当前路线、维护禁区

## 3. 推荐阅读顺序

第一次进入本仓：

1. `README.md`
2. 本文
3. `docs/控制系统总览.md`
4. `pwm_control_program/README.md`
5. `docs/控制安全与运行语义.md`
6. `docs/通信协议与遥测说明.md`

按问题深入：

- 改安全/模式/控制裁决：`docs/控制安全与运行语义.md`
- 改协议、遥测、bridge：`docs/通信协议与遥测说明.md`
- 改 PID、mixer、bench 回归：`docs/控制器调参与测试指南.md`
- 讨论下一步升级方向：`docs/演进记录与边界约束.md`

## 4. 文档收口原则

后续不再新增同类散文档，统一并入现有六份：

- 主链与目录说明：并入 `控制系统总览`
- 安全、状态机、interlock、PWM 保护：并入 `控制安全与运行语义`
- 协议、wire、SHM、遥测、ROS2 外围：并入 `通信协议与遥测说明`
- 控制器实现、调参、联调、测试：并入 `控制器调参与测试指南`
- 阶段性路线与历史决策：并入 `演进记录与边界约束`

不再单独保留：

- 一次性阶段计划
- 孤立测试报告
- 重复操作手册
- 与当前 authority 主线脱节的旧说明

## 5. Source Of Truth

控制侧事实优先级固定为：

1. `pwm_control_program/`、`gateway/`、`orangepi_send/` 真实代码
2. `UnderwaterRobotSystem/shared` 中的共享契约
3. 本仓六份中文基线文档
4. 系统文档仓中的系统级契约和 runbook
5. 历史阶段材料

若文档与代码冲突，以控制运行时代码和共享头文件为准，并在对应文档中补记录。
