# 通信协议与遥测说明

## 文档状态

- 状态：Authoritative
- 适用对象：修改 GCS 协议、gateway bridge、SHM 接口、`TelemetryFrameV2` 或 ROS2 外围桥的开发者

## 1. 协议与接口分层

当前控制仓的通信与接口可以按四层理解：

1. GCS wire 协议
   - 负责把远程控制请求送到机器人侧
2. gateway/SHM bridge
   - 负责把 wire 消息转成运行时可消费接口
3. 控制运行时接口
   - `ControlIntent`、`NavView`、`TelemetryFrameV2`
4. 外围镜像接口
   - GCS status 兼容映射、ROS2 mirror、诊断工具

不要把这四层混成一个概念。

## 2. GCS 控制请求

从 GCS 到控制侧的请求语义重点包括：

- 6DOF 控制量
- mode 请求
- arm/disarm
- estop
- `ttl_ms`
- 时间戳与序号

这些字段表达的是“我希望系统做什么”，不是“最终输出 PWM 应该是多少”。

## 3. gateway 的桥接职责

`gateway/gcs_server` 当前负责：

- 接收 UDP 会话
- 维护 session 状态
- 解析控制请求
- 写入 `/rovctrl_gcs_intent_v1`

`gateway/nav_viewd` 负责：

- 读取 `NavState`
- 做控制侧可消费投影
- 产出 `/rovctrl_nav_view_v1`

它们都不应接管最终安全策略。

## 4. `TelemetryFrameV2` 语义

`TelemetryFrameV2` 是当前 V1/P1 基线下的运行态权威视图，用于：

- 控制主循环可观测性
- 操作员诊断
- gateway 到旧状态协议的映射
- 后续 ROS2/diagnostics/UI 外围桥

它至少应稳定承载：

- 当前意图状态
- 当前控制执行状态
- 系统健康与 link 状态
- 导航相关状态快照
- 最近命令结果
- 最近事件记录

原则上：

- 旧 `StatusTelemetry` 只应作为兼容压缩视图
- UI 或 bridge 不得反向定义 `TelemetryFrameV2` 主语义

## 5. ROS2 的允许边界

ROS2 当前只允许处于外围层，例如：

- mirror
- diagnostics
- health monitor
- telemetry fan-out
- MotorTest orchestration
- UI backend

ROS2 不得成为：

- 最终 estop authority
- 最终 arm/disarm authority
- 最终 PWM arbitration
- 控制主循环 owner

## 6. 修改协议或遥测时的闭环

如果改动涉及：

- GCS wire 字段
- SHM 结构
- `TelemetryFrameV2`
- gateway 到 legacy status 的映射
- ROS2 mirror 布局

最低闭环是：

1. 更新本文
2. 更新系统文档仓对应契约
3. 验证直接生产者/消费者
4. 明确哪些兼容层仍旧存在，哪些行为已变化

不能只改一端然后期待其他模块“自己适配”。
